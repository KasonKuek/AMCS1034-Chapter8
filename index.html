1. GUI and event-driven programming

A graphical user interface (GUI) lets the user interact with a program through graphical elements such as buttons, menus and pictures, using a mouse and keyboard. A command-line interface (CLI) needs the user to type commands or text instead. A web browser and an office suite are GUI applications.

CLI (what we did before)GUI (this chapter)
The usertypes text and commandsclicks, types into boxes, drags, picks from menus
Inputinput(), in a fixed orderwidgets, in any order the user likes
Outputprint() to the consolechanges on the window: labels, drawings, pop-ups
Program flowalgorithm-driven: top to bottomevent-driven: waits, then reacts

Event-driven programming

In event-driven programming, external events (a click, a key press, a timer) decide what runs next. An algorithm-driven program expects its input in a fixed order and timing.

Algorithm-driven = following a recipe. Step 1, step 2, step 3… The cook decides the order. input() waits for exactly the answer it asked for.
Event-driven = a waiter in a restaurant. The waiter stands ready. When a customer raises a hand (an event), the waiter goes to that table and does the matching job (the event handler), then waits again.
1. Build the window
create widgets, place them
→
2. mainloop()
wait for events…
⇄
3. Event happens
click / key / timer
→
4. Handler runs
then back to waiting

So building a GUI application has two jobs: (1) configure the screen, creating and arranging the widgets, and (2) define the processes (functions) that run when each event occurs.

The MVC design pattern

MVC (Model–View–Controller) is a popular way to organise GUI code so the data is kept separate from the user interface.

Modelthe data and logic (the "back end")calculator: the numbers and add / subtract
Controllerthe link between view and modelbutton click → call add() → update the result
Viewwhat the user seesthe window, entries and buttons

Why? Each part can be changed on its own. You can redesign the window without touching the calculations, or reuse the same calculations in a different interface.

2. The tkinter library and widgets

  • Tk ("toolkit") is a cross-platform library of GUI widgets, created by John Ousterhout in the late 1980s. It is fast and simple.
  • tkinter (said "T-K-inter", short for Tk interface) is Python's standard interface to Tk. It is the only GUI framework built into the Python standard library, so nothing needs installing.
  • Tkinter with a capital T was for Python 2. In Python 3, write tkinter in lowercase.
  • To check it works, run python -m tkinter in the Anaconda Prompt: a small window showing the Tcl/Tk version should pop up.
  • Other Python GUI libraries exist, for example wxPython, PyQt and Kivy.

Widgets

3. Your first window: Label, pack() and mainloop()

from tkinter import *       # Import all definitions from tkinter

window = Tk()               # 1. Create a window (the parent)
lbl = Label(window, text = "Welcome to Python")   # 2. Create a label inside it
lbl.pack()                  # 3. Place the label in the window
window.mainloop()           # 4. Start the event loop
LineWhat it does
window = Tk()creates the main window. A widget with no parent is called a window.
Label(window, text = ...)the first argument is the parent container; the keyword text is what is shown
lbl.pack()a geometry manager places the label in its parent. Without pack() (or grid()), the widget is created but not shown.
window.mainloop()starts the event loop. The window only appears now, and the program stays here, waiting for events, until the window is closed.

Parent–child hierarchy. The window is the parent; the label is its child. Later, frames are children of the window and buttons are children of the frames, like folders inside folders.

Example 1A: Label(None, …)

With None as the parent, tkinter creates a default root window for you, and the module-level mainloop() starts the loop. It works, but 1B (create the window yourself) is clearer.

Example 1C: lbl.pack(expand = True)

When the user resizes the window, expand = True (or YES) gives the label the extra space, so it stays centred. Without it, the label stays at the top.

Two ways to import (Example 1D)

from tkinter import *
window = Tk()
lbl = Label(window, text = "Hi")
import tkinter
window = tkinter.Tk()
lbl = tkinter.Label(window, text = "Hi")

from tkinter import * is shorter, but it puts every name into your program, so it is harder to tell where a name like Label or END came from. import tkinter keeps every name labelled with tkinter.. The slides use the first style.

4. Buttons and event handlers

A button that was created without a handler does nothing when clicked (Example 2A). An event is produced, but the program isn't designed to handle it.

An event is a change in state caused by an action: a keystroke, mouse activity, a menu selection or a timer running out. Clicking a button produces an action event. To react to it, write a function and bind it to the button with command =.

def processOK():                    # the event handler (callback function)
    print("OK button is clicked")

btOK = Button(window, text = "OK", command = processOK)
#                                            ^ the function NAME, no brackets

These functions are called callback functions or handlers: you don't call them yourself; tkinter calls them back when the event happens.

The most common mistake: command = processOK() with brackets. That calls the function immediately, while the window is being built (so it prints once at the start), and gives the button its return value (None), so later clicks do nothing. Write command = processOK.

Example 2C: colours

fg (foreground) is the text colour; bg (background) is the fill. By default fg is black and bg is grey.

Button(window, text = "OK", fg = "red", command = processOK)
Button(window, text = "Cancel", bg = "yellow", command = processCancel)

Example 2D: side by side

Without side, pack() places widgets top to bottom. side = LEFT / RIGHT places them on the left or right.

btOK.pack(side = LEFT)
btCancel.pack(side = RIGHT)

5. Defining an event handler class (Example 3)

class ProcessButtonEvent:
    def __init__(self):                 # builds the GUI when the object is created
        window = Tk()
        btOK = Button(window, text = "OK", fg = "red", command = self.processOK)
        btCancel = Button(window, text = "Cancel", bg = "yellow", command = self.processCancel)
        btOK.pack()
        btCancel.pack()
        window.mainloop()

    def processOK(self):                # handlers are now methods
        print("OK button is clicked")

    def processCancel(self):
        print("Cancel button is clicked")

ProcessButtonEvent()                    # creating the object runs __init__()

Why put the GUI in a class?

  1. Reuse: the class can be used again in other programs.
  2. Shared data: methods can use instance data fields such as self.name or self.lbl, so a handler can read an entry or change a label that was created in __init__(). With plain functions you would need global variables.
Notice command = self.processOK: the handler is a method of this object, again without brackets. Widgets a handler needs later must be stored with self. (e.g. self.lbl); a local variable like window disappears after __init__().

7. Frames, check buttons, radio buttons, Entry, Message and Text

Frame

An invisible container for grouping widgets. Use frames to build a layout in parts, e.g. one row of check boxes and one row of entry + button.

Checkbutton vs Radiobutton

Check boxes: many can be ticked. Radio buttons: only one in a group can be selected. Radio buttons sharing the same variable form one group.

Entry vs Text

Entry is one line (a name, a number). Text holds many lines: insert(END, "…"), get("1.0", END), delete("1.0", END).

Message

Like a label, but it wraps long text over several lines automatically.

tkinter variables: why self.v1 = IntVar()?

A check box, radio button or entry keeps its value inside Tk, not in a normal Python variable. A tkinter variable links the widget and your program: when the user ticks or types, the variable changes automatically, and your handler reads it with get(). If you set() it, the widget updates on screen.

VariableHoldsUsed with
IntVar()an integercheck button (1 = checked, 0 = not), radio buttons with value = 1, 2…
StringVar()a stringEntry (textvariable =), radio buttons with value = 'R', 'Y'
DoubleVar()a floatnumbers with decimals
BooleanVar()True / Falseon/off settings
self.v1 = IntVar()
cbtBold = Checkbutton(frame1, text = "Bold", variable = self.v1,
                      command = self.processCheckbutton)

def processCheckbutton(self):
    print("check button is " + ("checked " if self.v1.get() == 1 else "unchecked"))

self.name = StringVar()
entryName = Entry(frame2, textvariable = self.name)   # Entry uses textvariable
print("Your name is " + self.name.get())               # read what was typed
Watch the option names: check and radio buttons use variable =, but Entry uses textvariable =. Also, self.v1.get() needs the brackets: self.v1 on its own is the variable object, not its value.

8. The Canvas widget

A Canvas is a drawing area. Canvas(window, width = 200, height = 100, bg = "white") makes one 200 × 100 pixels.

Coordinates: the origin (0, 0) is the top-left corner. x increases to the right, and y increases downward (unlike maths graphs). The bottom-right corner of a 200 × 100 canvas is (200, 100).

10. Geometry managers: pack, grid and place

A geometry manager decides where widgets go inside a container. tkinter has three:

ManagerHow it places widgetsUse it for
pack()stacks widgets top to bottom (default) or side by sidesimple columns or rows
grid()puts widgets in the cells of an invisible table: row, columnforms: labels next to entries
place()exact x, y positionsrarely: it doesn't adapt well to different computers, so avoid it
Don't mix managers in the same container. Using pack() and grid() for widgets in the same parent makes the window freeze or gives TclError: cannot use geometry manager grid inside . which already has slaves managed by pack. Use a Frame as a sub-container instead: pack the frames into the window, and grid the widgets inside each frame.

The pack manager

fillNONE (default), X, Y, BOTHstretch the widget to fill the space it was given: X = horizontally, Y = vertically
expand0 / False (default), 1 / Truegive the widget a share of the extra space when the window grows
padx, padypixelsempty space around the widget

About eval() in the calculator


def add(self):
    self.v3.set(eval(self.v1.get()) + eval(self.v2.get()))

  
self.v1.get() returns a string such as "2". eval() reads the string as Python, giving 2 (an int) or 4.5 (a float) automatically. But eval() runs any text the user types as Python code, which is a security risk, so it is rarely used in real programs. A safer choice is float(self.v1.get()), inside try/except ValueError in case the user types letters.

13. Animation

  
An animation is a sequence of drawings shown one after another. On a canvas, move(tags, dx, dy) moves a shape: a positive dx moves it right, a negative one left; a positive dy moves it down, a negative one up.

  


Slide version: a loop with update()
while True:
    canvas.move("text", dx, 0)
    canvas.after(100)      # sleep 100 ms
    canvas.update()        # redraw now
    if x < width:
        x += dx
    else:
        x = 0
        canvas.delete("text")
        canvas.create_text(x, 30,
            text = "Message moving?", tags = "text")


Better: after(ms, function)
def animate(self):
    self.canvas.move("text", self.dx, 0)
    if self.x < self.width:
        self.x += self.dx
    else:
        self.x = 0
        self.canvas.delete("text")
        self.canvas.create_text(self.x, 30,
            text = "Message moving?", tags = "text")
    self.canvas.after(100, self.animate)   # run again later

  

  
The slide version works on your computer, but the while True loop never returns to mainloop(): the program is stuck in the loop, and closing the window raises an error. after(100, self.animate) asks tkinter to call the function again in 100 ms and returns straight away, so the window stays responsive. That makes it easy to add Stop / Resume / Faster / Slower buttons (Example 15). The GUI Lab uses the after() version, because a loop that never ends would freeze the web page.
